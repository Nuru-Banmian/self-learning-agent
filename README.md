# 自我学习生活多 Agent 个人助理

通过日常聊天记录待办，在新会话中结合用户记忆、资料与天气生成当天计划。

- 主 Agent：统一对话并组织计划。
- 执行 Agent：查询资料、地点和天气。
- 学习 Agent：从日常对话整理用户记忆，在后续任务中使用。

已实现 Issue #2～#9 的功能：聊天创建、查询、修改和完成待办，按实际待办生成基础当天计划，明确接受后将行动建议加入待办；包含 SQLite 持久化、工作台及 HTTP/SSE。普通聊天可形成有来源的用户记忆，在新会话普通问答中使用。支持聊天纠正及面板编辑、删除记忆；可按需搜索学习资料并生成有来源的步骤与可选练习；支持目的地和日期天气查询、消歧与外出准备提示。真实百炼、IQS和和风已完成本机联调。首版面向本机单人使用。

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.lock
Copy-Item .env.example .env # 仅首次执行；已有 .env 时不要覆盖

npm run build
cd ..
.\.venv\Scripts\python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

打开 http://127.0.0.1:8000 。仅运行一个应用进程，不使用 `--workers`；关闭进程后用相同 `DB_PATH` 重启即可保留数据。默认数据库是 `data/assistant.sqlite3`。前端开发可另开终端运行 `cd frontend; npm run dev`，Vite 将 `/api` 转给 8000 端口。

在后端 `.env` 填写北京地域的 `DASHSCOPE_API_KEY`。`DASHSCOPE_BASE_URL` 默认使用仍受支持的北京兼容地址；也可填该账户的北京业务空间专属地址。不要将密钥放进前端或 `VITE_*` 变量。`.env`、数据库、构建和测试输出都已被 Git 忽略；修改 `.env` 后重启后端。无模型配置时，已保存待办仍能直接查看。

搜索与天气的凭据获取网站、控制台步骤和真实验证命令见 [外部 API 配置](docs/api-setup.md)。

固定模型为 `qwen3.7-plus-2026-05-26`，每次调用显式 `enable_thinking=false`，供应商 HTTP 客户端禁用环境代理。`.env.example` 可配置用户时区、单次模型超时、整轮时限、最多模型调用次数及失败重试次数。最多调用次数包含重试；只重试网络故障、限流及临时服务端故障，不重试鉴权错误或不合法输出。

## 使用与边界

- 输入“请记录明天学习 Python 生成器和整理书桌”，保存后页面读回实际日期和来源。
- 无日期可以说“请记录整理书桌”。支持今天、明天、后天、`YYYY-MM-DD` 和明确月日；省略年份且该月日已过去时先追问。其他日期表达、歧义或无法确认的授权会要求重新明确事项与日期，不猜测写入。
- 授权采用保守的中文指令校验，标题须对应本条消息原文。复杂转述、引用、建议、否定和问题不直接写入；澄清后请重新提交完整事项及日期。多个不同日期请用逗号分句，每个分句明确日期。
- 可以说“查询我的待办”“把整理书桌改到明天”“把整理书桌标题改为整理书架”“把整理书架标记完成”。修改与完成使用稳定 ID；同名、代词不清或多个目标会先澄清，可在列表展开“查看来源与标识”后指定完整 ID，或直接使用编辑和完成按钮。
- 列表区分今日未完成、逾期未完成、未安排、未来安排、已完成，按后端用户时区的零点划分；页面每分钟及重新获得焦点时刷新，也可手动刷新。不会自动将逾期事项迁到今天。
- “今天我该干什么？”或“生成当天计划”会查询真实待办并提出可选步骤，生成过程不修改待办。说“把建议标题加入待办”或点击对应“加入待办”，才创建一项；同一条建议只会转成待办一次。
- 建议按会话保存、关联来源计划和接受后创建的待办；页面明确显示加入后安排的具体日期（计划生成时的本地日期），旧建议不会随今天变化自动改期。多项建议时只说“加进去”会先追问。
- “新会话”保留待办，当前会话的行动建议独立展示。无模型配置时仍可查看列表，通过面板修改标题、日期、完成待办或接受已有建议；这些操作与聊天复用同一校验、事务及请求防重复规则。清空面板日期表示未安排。记忆独立跨会话保留；尚不支持外部任务执行。
- 同一 `request_id` 重复提交返回原状态；更换内容、会话或操作却复用标识返回 409。新的请求标识可再次创建相同文本。同一会话的新请求持久排队、按接收顺序执行；最多接受 10 条未结束请求，超出返回 409 且不创建消息，等队列空出后可重发。同一会话中下一轮只读取前一轮已提交的数据。
- 请求记录区显示排队、处理、完成、部分完成和失败/中断；刷新、断线或重启后通过普通状态接口恢复。断开 SSE 不取消后台执行，页面每两秒读回待确认请求，最终状态以数据库为准。
- 整批待办、成功事件、回复和执行终态一起提交；不会出现只有部分待办或虚假的成功事件。进程重启时将运行中和排队中的请求标记为中断，不自动重跑。此前已提交记忆或外部资料保留，存在有效部分时显示部分完成。
- “重试同一请求”用于确认未知结果；“重试未完成处理”显式创建关联原请求的新执行记录。重复点击只返回同一次重试；旧记录与事件保持不变。已完成请求、已提交待办/记忆修改/建议的部分完成请求只返回已有结果，不再次执行写入。仅学习记忆已提交而回答未完成时，可以重试回答，已处理来源不会再次学习或恢复已删除记忆。重试沿用原消息日期含义，并排在当时会话队列末尾；每次尝试有独立调用预算，需要用户再次明确重试才会产生下一次尝试。

## 用户记忆

- 普通表达即可学习，例如“我喜欢优先阅读官方资料”“我正在学习 Python”“今天只有半小时”，不需要说“记住”。学习 Agent 使用严格 JSON Schema 提出候选，应用校验后保存用户原文分句及来源；它没有写入工具。
- 为避免把猜测或转述变成事实，首版保守支持直接中文背景、偏好、今天/明天及明确任务条件。引用、假设、问题、待办和无法可靠识别的时间范围不自动保存。复杂表达请拆成完整陈述；这不是通用自然语言事实判定器。
- “今天”“明天”的边界由消息接收时的用户时区计算。任务条件必须包含唯一现有待办完整标题，并绑定其 ID；仅在问题明确涉及该任务且任务未完成时加载。混合日期与任务条件同时受两种限制。
- 记忆面板展示内容、类别、范围、有效时间、生效情况和原始消息。相近主题的潜在冲突会暂停双方生效并提示澄清。可说“更正：我住在上海”更新唯一对应记忆；不明确时会追问。也可用“把记忆 完整ID 改为 完整陈述”精确指定目标。
- 面板可编辑内容、主题、范围和期限，也可确认删除；不依赖模型或信息工具。内容与范围期限须一致，例如“今天只有半小时”搭配一般范围、仅今天；任务条件须包含完整待办标题并选择该待办。主题须取自内容原文。编辑不能引入另一条同时生效的矛盾记忆。
- 编辑、纠正和删除使用同一应用校验及事务，保存成功后读回。来源更新为本次聊天或面板操作消息；旧版本面板提交会被拒绝，避免覆盖其他会话的新修改。模型等待期间若记忆发生变化，本轮旧候选或回答会被丢弃，并提示重新表达或提问。
- 删除是停止后续加载，并保留屏蔽旧来源所需的记录；不清除原始会话历史。已处理来源不会再次学习，重试和重启不能恢复已删除记忆。之后重新明确表达会产生新来源，可重新形成记忆。
- 普通问答仅加载相关、生效的记忆：按主题词及中文相邻双字匹配，最多 6 条，序列化上下文最多 4000 字符，含来源消息和会话 ID。不会重放完整旧聊天；“这次”“本次”例外不加载一般偏好，也不永久改写偏好。已保存的任务限定条件优先于同主题的一般偏好。关键词检索可能漏掉同义表达。
- 页面和运行记录分开显示已保存、此次加载及主 Agent 的采用说明；采用说明不代表效果已验证。模型文字不作为保存回执。只有数据库提交后才出现 `memory_saved`。
- 学习在本轮终态前完成；回答可用但学习失败时为 `partial`（部分完成）。没有新增信息为正常完成。记忆已提交但回答失败也保留已保存结果并报部分完成。总模型调用预算包含学习、主 Agent 及重试，并为主 Agent 保留一次调用。

## 学习迁移证据与演示

- 页面底部“学习迁移证据”可选择当前会话回答，也可输入历史请求标识；已选记录刷新后保留。来源消息/会话、当时保存的记忆快照、本轮加载、主 Agent 采用说明和实际回答分别展示。删除或纠正记忆不会改写历史证据；历史加载不代表当前仍生效。
- 输入另一条已结束请求的标识可并排比较。对比检查点要求两条记录具有同一模型快照且实际发生过模型调用；旧记录未保存模型信息时不补造。模型版本一致只排除版本变化，不能单独证明记忆造成了行为变化。
- 填写具体检查标准、观察依据和“通过/失败/未验证”可保存人工检查点。默认未验证；采用说明不会自动判为通过。每条检查点保留时间、人工来源及基线请求，刷新和真实进程重启后可读回。检查点不代表首版整体通过，也不修改记忆或待办。
- 普通混合表达“我喜欢优先阅读官方资料，今天我要学习 Python 生成器”会分别学习偏好与记录待办。仅对完整、独立的日期意图分句识别；相邻“仅限今天”等范围不能被丢弃。资料搜索将本轮相关生效偏好附到实际查询中，删除/过期或当前例外排除的偏好不会附带；超长查询明确要求简化。
- 每次执行记录配置模型、调用次数/重试/超时预算；`model_result` 事件保存实际请求模式、HTTP 状态、耗时和供应商返回的可用 token 用量。未知用量为 null；配置模型不代表一定发生调用，错误响应正文不公开。
- 配置启动和重复演示步骤见 [Issue #9 演示说明](docs/acceptance/issue-9-demo.md)，逐项验收及真实服务缺口见 [Issue #9 验收记录](docs/acceptance/issue-9.md)。目前仍不能宣称首版完整交付。

## 学习资料与执行 Agent

- 例如“查找 Python 生成器的官方资料，并给一个练习”。主 Agent 结合真实待办、相关生效记忆提出查询；执行 Agent 是受限的确定性工具执行器，只能调用 IQS 搜索和读取返回资料的正文。主 Agent 再组织有来源的步骤，不是另一个拥有写入权限的模型。
- “今天我该干什么？”会结合当天学习待办检索资料偏好。明确“搜索/查找学习资料”的指令限定为研究工具，查询内容仍由主 Agent 组织；费用/方法咨询保留普通问答。仅查询待办或不需要外部资料时不强制搜索；网页数据不进入学习 Agent。默认生成 3–5 个可选学习任务，可逐项选择加入；明确数量优先于默认。建议通过既有接受建议路径加入，同一建议只能写入一次。支持“给我两个任务”“给我两个学习任务”“给我两个可选学习任务”等数量表达；只保存逐项选中的任务，未选项仍为建议。
- 后端 `.env` 单独填写 `IQS_API_KEY`，不会复用百炼密钥。`IQS_ENGINE=Generic`；`IQS_ENHANCED_SUMMARY=false` 默认关闭收费增强摘要。引擎/增强功能的费用与权限以 IQS 账户为准。
- `SEARCH_TIMEOUT_SECONDS=12` 限制每次实际请求，`MAX_SEARCH_CALLS=4` 包含搜索、正文读取和所有重试，`SEARCH_RETRIES=1`。仅网络、超时、429 和临时 5xx 可重试；鉴权/结构错误不重试。`RUN_TIMEOUT_SECONDS` 仍限制整轮，建议 `MAX_MODEL_CALLS=3` 以容纳学习、主 Agent 委派与最终组织。旧 `.env` 的显式配置不会自动覆盖。
- 每轮最多保存前 5 条资料、按需读取其中前 2 条正文。响应最多 512 KB，标题/摘要/正文分别最多 500/4000/10000 字符；正文截断标识可见。页面区分搜索摘要和实际取得的正文片段，不把摘要声称为已读全文。
- 页面及持久执行记录保留查询、输入摘要、角色、每次工具请求、状态、耗时及实际来源。结果区分 success/empty/partial/error；搜索无结果或失败不编造来源，正文或最终组织失败仍保留已有资料和待办。引用只能使用本轮实际来源标识，执行阶段不接受模型写入工具。
- 供应商客户端禁用环境代理。搜索 API 可达与本机打开结果网站可达须分别验证；本机大陆出口尚未证明，不能将禁用代理等同于大陆验收通过。

## 天气与外出准备

- 例如“查询明天上海天气，出门需要准备什么？”。也可针对已有未完成外出待办询问准备事项。缺少地点或日期会追问；不会从居住记忆或定位猜目的地。
- 重名或模糊城市会列出候选。请使用给出的地点 ID 和完整日期重新询问，例如“查询明天地点101071201天气”。当前不依赖旧聊天处理“第一个”等指代。
- 相对日期按消息接收时的用户时区解释，再匹配目的地该日预报；已有待办的绝对日期保持不变。页面显示实际地点、经纬度、时区、日期、天气数据、来源、查询时间与工具记录。未取得对应日期预报时不借用其他日期。
- 后端 `.env` 填写独立 `QWEATHER_API_KEY` 和账户专属 `QWEATHER_API_HOST`（只填完整域名，例如 `h2a9cf3mhs.xy.qweatherapi.com`，保留全部子域）。采用城市查询和逐日预报 v1；目的地不限中国。`WEATHER_FORECAST_DAYS=7`，可设 1–10 天，具体权限以账户为准。
- `WEATHER_TIMEOUT_SECONDS=12`、`MAX_WEATHER_CALLS=4`、`WEATHER_RETRIES=1` 限制城市/天气与重试共享预算，同时受整轮时限约束。无数据、超范围、权限错误和超时分别反馈，并保留已有待办与有效信息。
- 准备提示依据实际降水、温度和风速生成，只作为建议。点击加入或明确接受后沿既有路径保存一次，日期为出行日期。
- 真实调用：`.\.venv\Scripts\python -m tests.live_weather`。缺少配置明确跳过；`--mock-weather` 仅验证真实百炼与模拟和风协作。完整证据和未完成项见 [Issue #7 验收记录](docs/acceptance/issue-7.md)。

## 公开接口

完整 Schema：运行后的 `/docs`。

| 接口 | 用途 |
| --- | --- |
| `POST /api/sessions` | 创建会话 |
| `GET /api/sessions/{id}` | 读取会话、消息、有序 run_ids 和 latest_run_id |
| `POST /api/sessions/{id}/messages` | 提交 `{request_id, content, action?}`，返回 202 和执行状态；action 是用户明确选择的面板操作 |
| `GET /api/sessions/{id}/suggestions` | 当前会话的行动建议、来源执行标识、计划日期及转成的待办 ID |
| `GET /api/roadmaps`、`GET /api/roadmaps/{id}` | 跨会话路线列表与节点详情、持久资料和真实关联待办；接受节点复用 messages 的 `accept_roadmap_node` action，提交 `roadmap_id`、`node_id`、`expected_version` |
| `GET /api/runs/{request_id}` | 原子快照：执行状态、queue_position、关联 messages、有序 events、实际写入 ID、回复、调用计数、retryable/retry_of/retry_run_id，以及 memory/research/weather 证据 |
| `POST /api/runs/{request_id}/retry` | 无请求正文；显式重试失败或尚无主结果提交的部分完成请求，返回 202 及关联执行；重复调用返回同一子执行，已完成/已提交写入则返回原记录 |
| `GET /api/runs/{request_id}/events` | SSE：角色、工具调用/结果、保存、回复与终态，支持 `Last-Event-ID` |
| `POST /api/runs/{request_id}/checkpoints` | 保存人工检查点 `{id, criterion, observation, status, baseline_run_id?}`；status 为 passed/failed/unverified；同 ID 同内容防重复，冲突返回 409；结果由 GET run 的 checkpoints 读回 |
| `GET /api/memories` | 读取记忆、来源、范围、期限及当前是否生效，无模型也可查看 |
| `GET /api/todos` | 读取稳定 ID、标题、日期、状态、时间戳和来源 |
| `GET /api/todos/overview` | 后端本地日期和五组实际待办，与计划及页面共用分组规则 |
| `GET /api/health` | 基础状态、时区及是否配置模型，不暴露凭据 |

SSE 的 queued/角色/工具事件按实际处理顺序持久保存，保存事件仅在事务提交后可见；事件序号单调递增但不承诺连续。`Last-Event-ID` 只重放后续事件；回复当前以完整片段发出，不宣称供应商逐 token 流式输出。只有 terminal 标志整轮结束。排队等待不占模型调用预算，每次开始执行后受整轮时限约束；10 条队列上限及每轮最长 300 秒使本机会话等待有界。

后续角色/工具沿用同一请求状态与事务边界：领域写入必须与保存证据和提交标识一起提交，不能在供应商适配器中私自写库。学习步骤通过来源消息防重复，其余写入与主结果终态同事务；不声称对未来任意外部副作用提供 exactly-once。部署仍限单应用进程。

面板操作仍提交到 messages 接口，例：`action: {"tool":"update_todo","arguments":{"todo_id":"完整ID","title":"新标题","date_text":"2026-09-25"}}`。修改只提交需要变动的字段；`date_text: null` 清空日期。记忆编辑使用 `update_memory`，参数为 `memory_id`、`expected_source_id`（当前来源消息 ID）、`content`、`topic`、`scope`（general/task）、`task_id`（一般范围为 null）和 `validity`（ongoing/today/tomorrow/task）；删除使用 `delete_memory` 和这两个标识。维护验证接口 `reprocess_memory` 接受 `source_message_id`：已处理来源只返回不重复学习，其他来源要求用户重新表达。完成待办使用 `complete_todo` 和 `todo_id`；接受建议使用 `accept_suggestion` 和 `suggestion_id`。`content` 保存可读的操作描述。请求 ID 同时绑定文本、会话和 action，不能复用 ID 偷换操作。模型返回同类候选操作时，还必须通过原始聊天指令的授权与目标校验。
