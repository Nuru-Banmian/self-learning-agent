# Issue #22：节点完成进度与已掌握

日期：2026-09-21。规格：[Issue #22](https://github.com/Nuru-Banmian/self-learning-agent/issues/22)，父规格 #18。审查基线 `86739b46080b7966932347e48f8b7b71e579d33d`。

## 行为与边界

- 通过原有聊天或面板完成待办，关联路线节点同步完成。路线详情显示完成数、总数和剩余数；已加入但尚未完成的节点不计入完成数。
- 每个节点可选择“标记已掌握”。有待办时同步完成同一条待办，没有待办时不新建。聊天支持“把节点 完整标识 标记为已掌握”，唯一完整候选标题也可使用；不明确的目标要求重新选择。
- 新操作 `complete_roadmap_node` 复用公开消息入口，携带 `roadmap_id`、`node_id`、`expected_version`。面板与上述明确聊天命令不依赖模型或搜索；普通聊天完成待办仍沿用原有模型提议与独立授权校验。
- 同一 SQLite `BEGIN IMMEDIATE` 事务提交待办状态、首次节点完成事实、路线版本、运行快照、`roadmap_node_completed` 事件、回复与终态。完成事实保存时间、请求/消息/会话标识、用户原文、结构化操作、节点当时内容和资料快照。
- 节点完成事实以节点标识唯一约束。重复完成保留首次事实和时间，不改待办更新时间；重复标记或接受不产生新关联。独立会话的接受/完成在事务内检查当前状态；过期且未完成的目标拒绝，要求刷新确认。已有完成事实的重复操作可安全读回。
- 关联节点状态依据实际待办读回；无关联节点依据完成事实。后续编辑待办标题不改写完成快照。页面保留完整节点内容并可展开完成记录。
- 新表为增量升级；旧数据和旧完成状态保持可读。升级前已完成的节点没有当时的完成快照，不补造历史证据；本次完成入口写入的新事实有完整依据。
- 已提交完成操作纳入 `result_committed`，重放/显式重试返回既有结果。未提交的失败或进程中断可显式重试。撤销完成、删除、排期和路线调整不在本票范围。
