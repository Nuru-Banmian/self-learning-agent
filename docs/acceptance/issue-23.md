# Issue #23：按需预览并确认路线排期

日期：2026-09-21。规格：[Issue #23](https://github.com/Nuru-Banmian/self-learning-agent/issues/23)，父规格 #18。审查基线 `da5b0db2a8714684a219faa3197e87c1f9281169`。

## 行为与边界

- 普通学习意图生成无日期路线，接受节点沿用节点已确认日期；尚无日期时仍为未安排。生成新路线不同时推断排期授权。
- 明确要求排期后，真实模型提取原文中的路线、起始日期、时间预算、学习日和截止条件。应用校验原文依据并计算日期；模型不能直接写日期。否定、引用和说明性请求不触发方案；目标、日期或预算不明确时澄清。也可直接在路线面板填写条件。
- 本片对指定路线的全部未完成节点排期。支持统一的每个学习日分钟预算，以及每天、工作日、周末或明确列出的星期；缺少条件、复杂条件或部分节点排期要求先澄清，可改用面板表达。工作日指周一至周五，不读取法定节假日日历。无周期日历、提醒、外部日历及自动重排。
- 按路线顺序分配每日学习量；长节点允许跨天，节点日期为预计完成日。预览逐日列出分钟数、前后日期及关联待办影响。截止日为包含该日的最晚完成日期，预算不足不保存可行方案。相对日期以原请求接收时间及用户时区解释，跨日重试保留原请求时间。
- `preview_roadmap_schedule` 和 `confirm_roadmap_schedule` 复用公开消息/SSE 入口。预览只持久保存方案；确认在 SQLite `BEGIN IMMEDIATE` 内校验路线版本、完整节点及实际待办快照，再同时保存节点日期、关联待办、方案状态、请求快照、事件及终态。不会因排期创建待办。
- 确认遇到另一会话编辑/完成、接受节点或另一方案提交时拒绝过期方案，显示当前变化并要求重新预览。待办改期再改回也会使旧方案失效。已应用方案重复确认不再修改节点或待办。
- 清空日期同样先预览再确认；已完成节点和首次完成记录保持原状。普通待办编辑仍可用；已关联节点读回实际待办日期，未关联节点读回已确认计划日期。
- 新表增量创建，旧节点缺少计划日期时默认为空。已保存方案和日期的读取、确认、清空、接受不依赖模型。方案及已提交结果接入原有去重与显式重试契约。
