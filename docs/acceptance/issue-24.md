# Issue #24：路线调整预览与确认

日期：2026-09-21。范围：[任务 #24](https://github.com/Nuru-Banmian/self-learning-agent/issues/24)，对应总规格 LR-09～LR-12 的调整切片。

## 交付行为

- 在路线面板描述调整要求，或聊天明确指定路线及调整内容。主 Agent 判断是否需要新资料，执行 Agent 复用 IQS 实际搜索，之后生成候选内容。明确搜索要求不能被模型省略。模糊目标、多路线歧义、模型未给出实际差异时说明问题，不保存空方案。
- 也可在面板手动编辑草稿：目标、耗时、练习、完成标准、候选标题、来源、日期、顺序、新增或移出节点。草稿先生成持久化差异，再确认；无需模型即可使用。日期手动明确指定，自动分配学习日仍使用既有排期面板。
- 方案逐项显示前后内容、位置、日期和实际关联待办。修改已关联的未完成节点时要求明确勾选全部同步范围；拒绝或只确认部分范围时整份方案保持待确认。可另外生成只涉及未加入节点的新差异，单独确认。
- 预览不改变当前路线、待办、日期和完成记录。确认复用 `BEGIN IMMEDIATE`，将节点、已授权的待办标题/日期、方案状态、请求快照、SSE 与终态一起提交。调整不会自动把新增候选加入待办。
- 节点和待办关联保持原标识。已完成节点内容、日期及首次完成快照不可重写；新目标可创建新节点。移出当前顺序的节点保留在历史列表，待办入口仍可跳到对应历史内容；历史待办仍可完成并留下首次完成记录。
- 方案记录当前版本、节点和实际待办状态快照。另一会话加入、完成、改期或调整之后，旧方案确认显示冲突，要求重新生成。重复确认已应用方案、重复请求、SSE 重连和显式重试不重复执行。
- 新表增量创建，普通待办、排期和完成入口保持兼容。开始任务前已有的 `CONTEXT.md`、`HANDOFF.md` 和 `docs/plans/` 改动不纳入本任务提交。
