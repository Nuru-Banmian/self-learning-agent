## 实现与使用

主 Agent 使用 `prepare_outing` 委派确定性执行 Agent。执行角色仅可调用和风城市查询与天气读取；准备提示由应用依据实际数值生成，不允许模型编造预报或扩大工具权限。用户可问“查询明天上海天气，出门需要准备什么？”或引用已保存外出待办询问准备事项。

地点须来自本条询问或未完成待办标题，不能从居住记忆、IP 或定位猜测。缺地点或日期时要求完整补充；城市重名或模糊匹配时列出国家、省/州、城市和地点 ID，要求重新提交包含地点 ID 与日期的完整询问，例如“查询明天地点101071201天气”。不默认选第一个结果，也不重放旧聊天猜测指代。

相对日期按请求接收时刻的用户时区解释；目的地时区用于匹配计划日期的当地预报及预报范围。界面同时展示目的地时区与解析后的日期。已有待办的绝对安排日期保持原样。当前配置预报窗口默认 7 天，允许 1–10 天；过去、超窗口或缺少目标日期的结果不能借用其他日期。仅接受带时区的完整目的地日区间，并核实单位、有限数值和有效经纬度。

天气实际数据、来源、查询时间、实际调用和四类结果保存在 `runs.weather` 并通过 SSE `weather` 事件发布。页面分开呈现已有待办、外部事实和行动建议。准备提示使用降水、低温、高温和大风数值条件；无预报时不生成天气准备项。明确接受后复用现有建议保存事务，建议安排在出行日期，同请求重放及重复接受不多写。

配置仅在后端 `.env`：`QWEATHER_API_KEY` 与 `QWEATHER_API_HOST`，Host 填账户专属 `*.qweatherapi.com` 域名（不含协议/路径）。使用 `X-QW-Api-Key` 请求头，不复用百炼凭据。每次请求默认 12 秒、最多 4 次实际请求（包含城市、天气及重试），最多重试 1 次，整轮另受 `RUN_TIMEOUT_SECONDS` 限制。仅临时 HTTP 故障、限流及网络故障可重试；响应最多 512 KB；禁止环境代理与重定向，不公开供应商错误正文或凭据。
