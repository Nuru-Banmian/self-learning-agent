## 状态与重试契约

- 请求持久状态为 queued、running、completed、partial、failed。会话按数据库接收顺序执行，最多 10 条未结束请求；超过容量拒绝且不写消息。同一 ID 重复提交返回原记录，不能改变内容、会话或 action。
- 普通 `GET /api/runs/{id}` 在同一 SQLite 读事务中返回关联消息、有序事件、写入 ID、回复、调用计数、队列位置和重试关系。会话接口提供有序 run_ids，刷新不依赖原 SSE 连接或内存任务。
- `POST /api/runs/{id}/retry` 显式创建关联子执行，一次原尝试最多一个子执行，重复提交只读回已有子执行。原消息来源与接收日期保留，旧状态和旧事件不改写。下一次尝试需要对失败子执行再次明确重试。
- 完成请求直接返回原记录。已提交主结果写入（待办、记忆维护或行动建议）的 partial 请求只读回已有结果。学习记忆提交、后续回答失败时，重试只跳过已处理来源的学习，不恢复已删除记忆。保留原记忆保存标识作为来源证据，不再次发出保存事件。
- 待办、成功证据、回复、提交标识和终态共用事务。内存连接断开不撤销后台工作；启动时将未完成/排队请求结束为 interrupted，保留已提交的有效部分，不自动恢复长流程。
- 当前/后续角色均经同一调度、有限模型/工具预算及总执行时限；未知适配器错误转为脱敏终态并释放会话队列。新写入能力须沿用应用事务和提交标识，不能绕过应用校验。部署仅支持一个应用进程；不引入分布式队列或外部副作用的 exactly-once 承诺。
