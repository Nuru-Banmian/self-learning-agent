### 诊断、修复与边界

将 `9dc347b2cb/redis-retry.json` 的原始节点内容经模拟供应商重放至公开 HTTP/SSE，真实临时 SQLite 仍将它保存为 completed，形成失败回归。提交夹具 `tests/fixtures/issue33/redis_failed.json` 保留练习原文，仅投影生成字段并把来源 ID 映射到测试的 S1；完整真实来源仍在原证据目录。

根因是练习完整性要求仅存在于提示词；持久化前没有检查服务准备、缓存初态和节点间复用。新增 `app/exercise_checks.py` 对生成的常见 Python/Redis 脚本做静态前置检查：

- Redis 服务安装、启动、PING 和客户端依赖命令；使用 Ubuntu venv 时检查 `python3-venv` 安装。
- 可核对的专用固定键、不同节点不复用键、演示调用之前的顶层重置；更新函数内删除或首次读取后才删除不算初态准备。
- 不拒绝无键操作的 PING 节点，也允许重置前的直接 PING 检查；支持基础字符串、哈希与列表操作。
- 明确缺陷在发布路线前阻止保存，资料仍保留并说明原因。模型修改练习同样检查；不迁移、删除或重写历史路线，不限制用户手工编辑的旧载荷。
- 初次生成失败时，最多向模型提供一次原草稿和具体缺陷做定向纠正，仍使用原有 `max_model_calls` 与总超时；预算不足或再次失败直接结束。每份被拒绝草稿和原因保存在 `exercise_validation` SSE/请求事件中，不把它加入路线或待办。

这是一组有界静态检查，不是通用 Python/Redis 解释器、代码安全沙箱或预期输出证明。目前能核对直接 `redis.Redis` / `redis.Redis.from_url` 客户端、固定键和常见命令；复杂动态键、其他初始化形式和未覆盖命令会提示无法核对，可能需要重新生成更简单的练习。应用不自动执行教学代码。通过检查仍须做内容阅读和执行验证，不能据此宣布 SP-15 通过。
